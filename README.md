# MB275 monitor — уведомления о свободных студиях

Скрипт раз в 5 минут открывает страницу floorplans в headless-браузере
(Playwright) и присылает тебе сообщение в Telegram, как только на странице
пропадает надпись "Floor plan details not available" (то есть появляется
жильё / кнопка BOOK NOW).

Headless-браузер нужен потому, что сайт защищён Cloudflare — обычный
`requests`/`curl` запрос почти наверняка будет заблокирован или получит
капчу вместо реальной страницы.

## Важно: robots.txt и условия сайта

У `mb275.securerc.co.uk` в `robots.txt` стоит `Disallow: /` — то есть сайт
явно просит ботов вообще ничего не индексировать/не обходить. Плюс на
странице явно предлагают записаться в **INTEREST LIST** как официальный
способ узнавать о доступности. Технически ничего не мешает поставить этот
монитор (это не взлом, не перегрузка сервера — один запрос раз в 5 минут),
но по-хорошему стоит параллельно записаться и в их лист ожидания, а
частоту проверки не делать выше, чем нужно. Используешь на свой риск: если
IP когда-нибудь получит блок от Cloudflare, самое простое — увеличить
интервал в config.json.

## 1. Создать Telegram-бота и узнать chat_id

1. В Telegram открой **@BotFather** → `/newbot` → следуй инструкциям →
   получишь токен вида `123456789:AAExampleTokenString`.
2. Напиши своему новому боту любое сообщение (просто "привет") — это
   нужно, чтобы бот "увидел" тебя.
3. Узнай свой chat_id — самый простой способ: открой в браузере
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates` (подставь токен)
   после того как написал боту, и найди там `"chat":{"id": ЧИСЛО, ...}`.
   Либо напиши `/start` боту **@userinfobot** — он сразу пришлёт твой id.

## 2. Настройка (это делает install.sh автоматически)

- `config.json` создаётся из `config.example.json` — впиши туда
  `telegram_bot_token` и `telegram_chat_id`.
- `check_interval_seconds` — по умолчанию 300 (5 минут).

## 3. Установка на Mac

Всё уже лежит в `~/Projects/mb275-monitor`. Единственный шаг, который
нельзя сделать за тебя из чата: регистрация фоновой службы macOS
(launchd) должна выполняться из настоящего Terminal на самом Mac — Claude
не может напрямую управлять твоим launchd. Всё остальное (код, venv,
установка зависимостей, сама служба) настраивается одной командой.

Открой **Terminal.app** и выполни:

```bash
bash ~/Projects/mb275-monitor/install.sh
```

Скрипт:
- проверит python3;
- если `config.json` ещё нет — создаст его из примера и попросит вписать
  токен/chat_id (после этого запусти команду ещё раз);
- поставит venv + зависимости + Chromium для Playwright;
- сделает один тестовый запуск (посмотри `monitor.log`, если что-то не так);
- зарегистрирует фоновую службу launchd, которая с этого момента сама
  проверяет сайт каждые 5 минут, включая после перезагрузки Mac.

## Полезные команды

- Посмотреть логи: `tail -f ~/Projects/mb275-monitor/monitor.log`
- Остановить и удалить службу: `bash ~/Projects/mb275-monitor/uninstall.sh`
- Проверить руками прямо сейчас:
  `~/Projects/mb275-monitor/.venv/bin/python3 ~/Projects/mb275-monitor/monitor.py --once`
- Если Cloudflare всё же блокирует: в `config.json` попробуй
  `"headless": false` (браузер будет виден, реже блокируется) или
  увеличь `check_interval_seconds`.

## Как это решает "кто первый — того и тапки"

Как только на странице пропадает фраза о недоступности (или меняется
контент при уже доступном жилье), бот сразу шлёт тебе сообщение со
ссылкой на страницу и, если получилось их найти, прямыми ссылками на
кнопки BOOK NOW. Дальше — вручную, руками, как можно быстрее.

## Вариант "работает даже когда Mac выключен" — GitHub Actions

Локальный launchd-вариант (выше) работает только пока Mac включён/не спит.
Чтобы проверки шли и при выключенном/закрытом ноутбуке, в папке уже готов
GitHub Actions workflow (`.github/workflows/monitor.yml`) — GitHub сам
будет запускать проверку каждые 5 минут на своих серверах.

Минусы этого варианта (уже видел, но на всякий случай ещё раз): точность
"раз в 5 минут" не гарантирована (GitHub иногда задерживает scheduled
запуски), и IP у GitHub-раннеров — облачный дата-центр, что теоретически
чуть повышает шанс, что Cloudflare когда-нибудь начнёт их блокировать
жёстче, чем твой домашний IP.

**Важно:** чтобы это было бесплатно (а не 2000 минут/месяц лимита),
репозиторий должен быть **публичным** — у публичных репо Actions
безлимитный и бесплатный. В коде нет ничего чувствительного — токен и
chat_id живут только в GitHub Secrets, не в самом репозитории.

### Шаги (сделай сам, я не могу создавать аккаунты/репозитории за тебя):

1. Создай новый **пустой публичный** репозиторий на github.com (без
   README/gitignore — просто пустой), например `mb275-monitor`.
2. В терминале на Mac:
   ```bash
   cd ~/Projects/mb275-monitor
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/mb275-monitor.git
   git branch -M main
   git push -u origin main
   ```
3. На странице репозитория: **Settings → Secrets and variables → Actions
   → New repository secret** и добавь два секрета:
   - `TELEGRAM_BOT_TOKEN` — твой токен бота
   - `TELEGRAM_CHAT_ID` — твой chat_id (634501437)
4. Всё, GitHub сам подхватит workflow и начнёт проверять каждые 5 минут.
   Прогресс/логи смотри во вкладке **Actions** репозитория.

Если запускаешь и локальный launchd, и GitHub Actions одновременно — оба
будут слать уведомления независимо друг от друга (получишь два сообщения
вместо одного), это не страшно, но выбери что-то одно, если не хочешь
дублей. Раз тебе нужно "даже при выключенном Mac" — GitHub Actions
достаточно сам по себе, локальный launchd можно не ставить.
